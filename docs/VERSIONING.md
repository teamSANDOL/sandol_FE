# 앱 버전 규칙

`pubspec.yaml`의 `version: <이름>+<빌드 번호>` 하나로 Android `versionName`/`versionCode`,
iOS `CFBundleShortVersionString`/`CFBundleVersion`이 정해진다.

## 버전 이름: `0.<마이너>.<패치>`

- **마이너**: 기능 묶음 단위. 화면 개편·새 탭처럼 사용자가 체감하는 변화가 모이면 올린다.
- **패치**: 같은 마이너 안의 빌드마다 올린다. 테스트 배포(NAS 등)용 빌드를 새로 만들 때마다 +1.
- 정식 출시 전까지 메이저는 0으로 둔다.

| 버전 | 의미 |
|---|---|
| 0.2.0 | 2026-10-21 기준 main (규칙 도입 이전 상태) |
| 0.3.x | 로그인 보안, 스플래시, Figma 최신 디자인(공지·학식·맵 탭 등) 반영 |

## 빌드 번호: `마이너 × 1000 + 패치`

- 0.2.0 → 2000, 0.3.0 → 3000, 0.3.7 → 3007.
- Android는 빌드 번호가 커져야 업데이트 설치가 되므로 항상 증가해야 한다. 패치는 999를 넘기지 않는다.
- 같은 번호로 서로 다른 APK를 배포하지 않는다.

## 올리는 방법

- 기능 브랜치는 버전을 바꾸지 않는다. 버전은 배포용 빌드를 만들 때 한 번에 올린다.
- 배포 빌드 직전 `pubspec.yaml`의 `version`을 올려 커밋하고, 빌드 산출물 이름에 버전을 넣는다.
  예: `sandori-0.3.1+3001-release.apk`
- 커밋 없이 시험 빌드만 할 때는 `flutter build apk --build-name=0.3.1 --build-number=3001`.
